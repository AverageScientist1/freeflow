# Security and privacy

Reviewed for version 0.11.1. This describes what was checked, how to repeat it, and what **cannot** be claimed.

## What the program does with your data

- **Everything happens on your computer.** FCS files are read from disk and analysed in memory. Results (Workbench `.ffwb`, CSV, PNG, HTML) are saved only where you choose in the file dialog.
- **No network.** The application code (`src/`) contains no network calls (`fetch`, `XMLHttpRequest`, `WebSocket`, `http`, `https`, `net`, beacons), no `http(s)://` address, no telemetry, no automatic updates, no accounts and no sign-in. In a real run, the program left open for 25 seconds had **no external TCP connection and no UDP endpoints**.
- **Nothing is sent to anyone**, and the program reads nothing you do not give it: it does not scan folders, does not look at other programs and does not touch the clipboard except when you press *Copy the file path*.
- **The only thing saved without asking** is preferences in the window's local storage: theme, CSV number format, thumbnail size and panel sizes. They contain no sample data.

## How the window is protected

- The page code has no access to Node.js (`nodeIntegration: false`), is isolated (`contextIsolation: true`) and runs in the system **sandbox** (`sandbox: true`). It can call only a few named functions of the bridge (`src/preload/index.ts`): open and save files through the system dialogs, and show a file in its folder.
- A **Content Security Policy** in the packaged version allows only the program's own code (`script-src 'self'`): no external or inline scripts.
- The window **cannot open other windows or navigate to another page** (it is refused) and **grants no permission** (camera, microphone, location, notifications…).
- The HTML report is shown in an isolated frame (`sandbox`), and any text typed by a person or read from a file is escaped before it goes into the report.

## What the distributed package contains

`app.asar` holds only: `out/main/index.js`, `out/preload/index.js`, `out/renderer/*` (the page, its stylesheet and two scripts) and `package.json`. On Windows, `Freeflow.exe` is **the same file as `electron.exe`**, untouched (same SHA-256 as the official Electron distribution). The dependencies built into the program are React, zustand, lucide-react and umap-js, all open source.

## What is in the repository

- No sample data and no real FCS files (the tests generate synthetic data).
- No passwords, keys, tokens or personal addresses (searched for strings such as email, user name, user paths, `secret`, `token`, `password` and private keys).
- The GitHub workflow (`.github/workflows/build.yml`) **uses no secrets** beyond the automatic `GITHUB_TOKEN`: it builds, uploads the programs as artifacts and, for a tag, attaches them to a release.
- No code, image, icon or file from another commercial program: the icon is generated by `scripts/make-icon.mjs`, and the design and texts are original. The project is published under the **MIT** license (`LICENSE`; notices for the included libraries are in `THIRD-PARTY-NOTICES.md`).

## Known vulnerabilities in dependencies

`npm audit` reports **15 moderate-severity advisories and none high or critical**. All of them are in the tools that build the installer (`electron-builder` and its dependencies `minimatch`, `glob`, `rimraf`, `ejs`…), which **are not part of the installed program**. No library that ships inside the program has advisories. Check with `npm audit` and update `electron-builder` when a fixed version is released.

## What cannot be claimed

- The program is **not code-signed** (no publisher certificate): Windows and macOS may warn about it or block it for that reason, not because it contains anything harmful. People who download the installers cannot verify who made them. Each release lists SHA-256 checksums so a download can be compared with what was published.
- **Chromium and Electron** (the engine underneath) are heavily audited third-party software; their code was not reviewed. No network traffic was observed, but that is a one-time check, not a guarantee.
- The **Mac** version has been built and its interface tests run on a Mac machine in GitHub Actions, but it has not been tried by hand on many real Macs.
- This review was done by the program's own authors; for critical use, an independent review is advisable.

## How to repeat it

```
# network calls and addresses in the code (nothing should appear)
grep -rnE "fetch\(|XMLHttpRequest|WebSocket|https?://" src
# dependencies
npm audit
# connections of the running application (PowerShell)
Get-NetTCPConnection -OwningProcess (Get-Process Freeflow).Id | ? { $_.RemoteAddress -notin '127.0.0.1','::1','0.0.0.0','::' }
```
